# Third-party notices

Ideas credited (no code copied): Treeship (Apache-2.0), whose JCS module's rule of refusing floats and unsafe integers is the basis of our canonical encoding profile.

Depended on (not copied): nearai-inference-sdk 0.2.1 (MIT) for NEAR AI Cloud attestation verification.

No third-party source files are copied into this repository yet. Each component adopted from another project is listed here with its project, licence and what was taken, and its licence text is kept in `third_party/`.

Secret detection (`crates/kk-secrets`): about 190 provider token layouts (prefix, alphabet, length) follow public formats also documented by the gitleaks rule set (MIT, https://github.com/gitleaks/gitleaks, studied at commit 5f6ec56); the ways a value is written around a key (INI, JSON, XML, YAML, several languages, Makefile) and the decoding of percent and unicode escapes follow behaviour read in its generator and `codec` package. No gitleaks source or rule file is copied; the benchmark samples it generates are used locally and are not stored here. False-positive filtering ideas (templated and indirect values, entropy, sequential alphabets) and the detection of a credential written into a comparison and of more password names follow the behaviour of detect-secrets (Apache-2.0, studied at commit 5e14193); no code is copied. Prompt-injection and egress-variant ideas were studied in promptfoo (MIT) and AgentDojo (MIT); no code is copied.

Web fetching (`crates/kk-fetch`): the address classes that are always refused (loopback, private, link-local, carrier-grade NAT, cloud metadata addresses and their IPv4-mapped, NAT64, translated and 6to4 spellings), the rule that every redirect target is validated again, and the refusal of credential-named query parameters follow the behaviour documented in Hermes Agent's `tools/url_safety.py` (MIT, https://github.com/NousResearch/hermes-agent). No source is copied; the implementation is written for this project.

Memory recall (`crates/kk-memory/src/fuse.rs`): the reciprocal rank fusion rule (sum of 1 / (60 + rank)) and the candidate-pool sizing (eight times the limit, between 64 and 512) follow the algorithm in Anamnesis's `crates/search/src/hybrid.rs` (Apache-2.0, https://github.com/Trapezohe/Anamnesis, copyright Trapezohe). The code is written for this project and no file is a modified copy, so no per-file change notice applies; the Anamnesis licence and NOTICE are kept in `third_party/` when any of its files are ever copied.

Backup (`crates/kk-backup`): the shape of the sealed envelope (versioned header naming its algorithm, random nonce, context bound as associated data) follows the structure in Ghast's `companion_service/crates/companion-checkpoint/src/sync.rs` (MIT, copyright 2025 Trapezohe). No source is copied. Depends on chacha20poly1305, hkdf and sha2 (RustCrypto, MIT or Apache-2.0).

Conversation summaries (`crates/kk-service/src/compaction.rs`): the idea of summarising the older part of a conversation under fixed headings while keeping the newest turns word for word, starting at one of the owner's turns, follows OpenCode's `packages/core/src/session/compaction.ts` (MIT, https://github.com/sst/opencode). No source or prompt text is copied; the wording and the safety checks are written for this project.
Memory near-duplicate grouping (`crates/kk-memory`): the idea of a read-only report of look-alike notes follows Anamnesis (Apache-2.0, `crates/store/src/semantic_dedupe.rs`); the grouping, the order-aware claim check and the thresholds are written here and no Anamnesis code is copied.
Signed updates (`crates/kk-update`, `kk-fetch`, `kk-evidence`): the rules for a signed root with rotation, thresholds of distinct keys, a rotation limit and recovery from a stolen key follow The Update Framework (python-tuf, MIT or Apache-2.0, studied at commit 31bba85); the rule that a key may be rotated but not removed follows Sparkle (MIT, commit 14fdbf2); what a package signature must bind follows the Tauri updater (MIT or Apache-2.0, commit 685d342). No code from any of them is copied.
Web search (`crates/kk-fetch`, `kk-service`, `kk-tui`): the freshness window follows the idea in the Cline SDK's web-search example (Apache-2.0, commit e68a6dd) and maps to SearXNG's `time_range` parameter; the study of provider failover and cooldown came from OpenCode (MIT, commit fe04656) and was not adopted. SearXNG (AGPL-3.0) was run and read for behaviour only; no code, text or layout was taken. No code from any of them is copied.
Sandbox system-call filter (`crates/kk-sandbox`): the choice of which calls to refuse (non-Unix sockets, io_uring, ptrace, process_vm_readv/writev) and the reason for refusing io_uring follow the Codex Linux sandbox (Apache-2.0, commit f2b94ef). The filter program, its delivery to bubblewrap and all tests are written independently; no Codex code is copied.

Memory recall benchmark (`crates/kk-cli/src/recall_bench.rs`, `scripts/recall-bench-prepare.py`): the retrieval protocol and metric definitions follow LongMemEval (MIT, Di Wu et al., https://github.com/xiaowu0162/LongMemEval); the code is written here. The dataset (cleaned `longmemeval_s`, MIT per its dataset card) is downloaded at run time and is not part of this repository.

Agent leases (`crates/kk-service`, `crates/kk-cli/src/mcp.rs`, `agent.rs`): the idea of limited, expiring, revocable grants whose uses are spent atomically follows IronClaw's capability lease store (Apache-2.0 or MIT, https://github.com/nearai/ironclaw, `crates/kernel/ironclaw_authorization`) and the rule ordering of OpenCode's permission service (MIT, `packages/core/src/permission.ts`); the code is written here and no file is a copy.

Memory merge (`crates/kk-memory`): the idea of archiving look-alike notes under a surviving note, never deleting them, follows ghast-memory-os (Apache-2.0, Trapezohe, `src/kernel/consolidation.ts`); the grouping, the owner-confirmed merge and the undo are written here and no Ghast code is copied.

Injection reader (`crates/kk-types/src/injection.rs`): the list of chat-template special tokens that are removed from data before a model sees it, and the idea of folding look-alike and invisible characters before matching, follow OpenClaw (MIT, OpenClaw Foundation, `src/security/external-content.ts`, commit f38495f7d); the token names are public template vocabulary and the matcher, the other views, the rules and the measurements are our own. Goose's security patterns (Apache-2.0, `crates/goose/src/security/patterns.rs`) were read and not used: they target shell commands, not text addressed to a model.

Fix format (`crates/kk-review/src/check.rs`): the idea of locating several changes of one file against the original and applying them together follows OpenClaw's apply-patch (MIT, OpenClaw Foundation, `src/agents/apply-patch-update.ts`, commit f38495f7d), itself a port of the OpenAI Codex `apply_patch` grammar (Apache-2.0); the exact-once, order-free and overlap rules, the joining into one change and the diff are our own.

Forgetting a review (`crates/kk-memory`): the rules (a selected source removes an entry whole, the decision is recorded before removal and checked by every way back in, repeating is harmless, a dry run reports counts) follow OpenClaw's memory purge as documented in `docs/concepts/memory-provenance.md` (MIT, OpenClaw Foundation, commit f38495f7d); the implementation is our own.

Attached files (`crates/kk-parse`): the ideas of decoding text as UTF-16 by byte-order mark, then UTF-8, then Windows-1252, of writing each sheet's dates as ISO dates while keeping long numbers exact, and of a parse-only mode that stores nothing follow the AnythingLLM collector (MIT, commit eda0eb5, `processSingleFile/convert/asTxt.js`, `asXlsx.js`, `asDocx.js`); no code is copied. Depended on (not copied): lopdf (MIT), quick-xml (MIT) and zip (MIT).

Note freshness (`crates/kk-memory/src/retention.rs`): the idea of halving a note's weight every fixed number of days since it was last recalled or written, with a log-scaled bonus for use, follows ghast-memory-os (Apache-2.0, Trapezohe, `src/kernel/retention.ts`, read in full). The half-lives, the weights, the bounded use as a nudge to the match score and the use record are written here; no Ghast code is copied.

Personal-data allowlist (`crates/kk-secrets/src/pii.rs`): the idea of an operator-owned list of exact values, patterns and domains that the personal-data notice leaves out follows Privateer's `src/config/piiAllow.ts` (MIT, Hayden Bulk Tech Labs, read in full with its test); the entry rules, matching, storage and the count of left-out values are written here and no Privateer code is copied.

Pattern rules (`crates/kk-review/src/pattern.rs`, `rules/patterns.yml`): Semgrep (LGPL-2.1, Semgrep, Inc.) is run as a separate program the owner installs and names in `KAKU_SEMGREP`; it is not linked, bundled or modified, and none of its registry rules are used. The rules in this repository are written here.
