
## Review against Chrome's extension security guidance (ledger F-X6)
- Guidance read by me, from the live pages: "Improving security in Manifest V3" (developer.chrome.com/docs/extensions/develop/migrate/improve-security): the first part, no `eval`/`new Function`/`executeScript` of strings, no remotely hosted code, bundle libraries; and "Stay secure" (.../security-privacy/stay-secure) up to and including "Use content scripts carefully" (about the first 5,000 characters): protect the developer account with two-factor sign-in, never use HTTP, request minimal permissions and host permissions, limit manifest fields, restrict `externally_connectable`, keep web-accessible resources to a minimum, set an explicit content security policy, avoid `document.write` and `innerHTML`, use content scripts carefully. NOT READ: the rest of "Stay secure" and the Chrome Web Store program policies (the review before a store listing needs them).
- Checked against `apps/extension`, each item with its evidence: permissions are `contextMenus` and `storage` only and the one host permission is `http://127.0.0.1/*` (tests ex06, which also bans `tabs`, `scripting`, `activeTab`, `cookies`, `webRequest` and others); no `externally_connectable`, `web_accessible_resources`, `content_scripts` or `nativeMessaging` (ex06); an explicit policy `script-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` with no `unsafe-inline`, `unsafe-eval` or remote source (ex07); no `eval`, `new Function`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `importScripts`, inline script or inline handler, and every URL in the sources is the loopback address (ex08); the popup loads only `popup.css` and `popup.js` (ex09). The service worker registers only a context-menu click handler: it has no `runtime.onMessage` or `onMessageExternal` handler, so there is no sender to check. Requests use `credentials: "omit"`, `cache: "no-store"` and `redirect: "error"` (lib.js).
- One departure from the guidance, on purpose: "never use HTTP". The extension speaks plain HTTP, but only to the program on the same computer (`127.0.0.1`), where there is no network path to eavesdrop on and a certificate would add nothing; Chrome treats loopback as a secure context. Every other address is refused by the host permission and by test ex08.
- Result: no change to the extension was needed; the guidance review is now recorded. Owed before a store submission: the rest of "Stay secure", the program policies, and two-factor sign-in on the publisher account (a person's step: HUMAN.md).
