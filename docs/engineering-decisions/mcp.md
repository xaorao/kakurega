
## Resources and a prompt (ledger D-D24, D-D25, D-D26)
- Reference: the official Rust SDK (`rmcp`, Apache-2.0, `crates/rmcp/src/model/resource.rs` read in full, `prompt.rs` core types read) for the exact wire shapes: `Resource` (uri, name, title, description, mimeType), `ResourceTemplate` (uriTemplate), `ResourceContents` (uri, mimeType, text), `Prompt` (name, title, description, arguments with required), `PromptMessage` (role, content). The server itself is hand-written already (decision in this file); only the shapes were taken. NOT READ: the SDK's server handler traits and the spec pages for resource subscriptions.
- Decision: BUILD. A resource or prompt is a second door to code the tools already guard, so it gets no logic of its own: a read runs the same tool through the same `call` (lease, output-schema check, audit under the tool's name). Listing and reading both require the backing tool to be visible under `--read-only` and `--allow`.
- Beats the usual implementation: the common MCP servers list resources unconditionally. Here an address that is not exactly a listed shape never leaves the process (no path, no query, no encoding tricks), a prompt is hidden unless every tool it uses is allowed, and prompt values are inserted as quoted text and refused if they contain control characters.
- Evidence: mc35–mc41 in kk-cli (listing, capabilities, read equals tool, 17 hostile addresses, 7 argument shapes, gating under allow/read-only, audit names, service down), live in `mcp_live.py` (51/51), 19 mutants all caught, `scripts/docs_check.py` now also compares the document's resources and prompts with the server's.
- Not covered: resource subscriptions (not offered, advertised as `subscribe: false`); clients other than the scripted ones (no real MCP client was driven); prompt text quality against a real model (needs a model).

## Installing the server into a client (ledger D-D38)
- Client formats VERIFIED from the vendors' pages, fetched through the reader proxy: Claude Code `claude mcp add --transport stdio <name> -- <command> [args...]` (https://code.claude.com/docs/en/mcp, "stdio servers"); Claude Desktop `claude_desktop_config.json` with `mcpServers` entries of `command` and `args`, macOS `~/Library/Application Support/Claude/` (https://modelcontextprotocol.io/quickstart/user; the file also exists on this Mac without any server entry); Cursor `mcp.json` with `type: "stdio"`, `command`, `args`, project file `.cursor/mcp.json` (https://cursor.com/docs/context/mcp). NOT VERIFIED: Cursor's global file path (not on the fetched page), and whether the proxy dropped it from a code block.
- Hermes `mcp_security.py` (read earlier, trace row) blocks client config entries that match attack indicators at save and at spawn. That guards a tool that writes configs. Kakurega does not write them, which removes the attack class: a planted config is the owner's to place, and the printed text names the binary by full path and digest so a swapped file is visible.
- Decision: BUILD `kaku mcp install --client NAME --print`. `--print` is required so a script cannot believe a file was changed; the command has no write mode. No token is ever part of the text: the server resolves it from the data folder at start, and the test plants a token in `admin.json` and in the environment and checks neither appears.
- Beats the docs-snippet approach: the path is the real binary, the limits are carried (and an unknown flag or tool name is refused, so a typo cannot print a config that widens access), shell quoting is checked against a real `sh` for 14 awkward paths including `$(...)`, backticks, quotes and newlines, and the printed command is run to prove it starts a server with the same limits.
- Evidence: kk-cli `mi01`–`mi08`, live `mcp_live.py` 52/52, 14 mutants all caught; a debug-build speed fix (`sha2` optimised in dev and test profiles) because hashing an 80 MB debug binary took 2 s per call.
- Not covered: Windows (the Claude Code line is refused there by code that no test runs; the JSON form is unexercised on Windows), a real Claude Desktop or Cursor loading the printed block, quoting for fish or PowerShell.
