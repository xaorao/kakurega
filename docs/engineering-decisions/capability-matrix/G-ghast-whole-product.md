# Capability matrix G: Ghast AI, the whole product

Scope: every Ghast capability that could be found in the local copies, judged for fit with Kakurega's kernel-mediated, privacy-first model. No code or existing file was changed; this is the only file written.

Evidence labels used in the "how it works" column: [V] read in code or a manifest at the cited lines; [D] stated in Ghast's own documentation, not confirmed in code; [O] observed on screen or in the shipped files (benchmark doc and screenshots, not re-run); [I] my inference. "NOT VERIFIED" means exactly that. Kakurega state: HAS / PARTIAL / LACKS / WORSE. Decision: REUSE (permissive code copied, notices kept) / ADAPT (algorithm or small code taken, notices kept) / IMPROVE (ours exists, strengthen) / BUILD (rebuilt from behaviour) / EXCLUDE.

Capability ids here are `GH-nn`, to avoid clashing with the `G`, `H` and `N` ids in `program/parity_registry.json`. Where a registry id applies it is named.

## 3. Implementation order (top 15)

Order is by user value and dependency, not by effort. Permissively licensed Ghast code named where it helps; everything else is behaviour only.

1. Readiness and self-check with one-click repair (GH-76, GH-01, GH-08). ADAPT the report shape from `companion_service/crates/companion-cli/src/main.rs` 808-927 (MIT). A stranger must reach a first review unaided.
2. Project entity, history, Cmd+K search, theme, greeting, locale scaffolding (GH-06, GH-23, GH-07, GH-08). Own build. This is the largest "feels like Ghast" gap.
3. Memory recall that shows used and withheld notes with reasons, with label filtering inside the SQL query (GH-44, GH-50; matrix E M7 and M11). ADAPT the reason enum and presets from `ghast-memory-os/src/kernel/types.ts` 830-845 and `disposition.ts` (Apache-2.0).
4. Hybrid recall: vectors inside the vault plus RRF (GH-45). ADAPT `Anamnesis/crates/search/src/hybrid.rs` (Apache-2.0): rank fusion, pool floor 64 and ceiling 512. Vectors carry the memory's label and die with it.
5. Durable runs: reconnectable event stream, orphan marking, run tiers (GH-74, GH-75, GH-34). ADAPT `companion-runtime/src/persist.rs` and `companion-agent/src/persist.rs` `mark_orphans` and the tier constants in `companion-shared/src/lib.rs` 154-190 (MIT).
6. Coding mode completion: checkpoints, rollback, test-output pane (GH-32). Own build; references in matrix E.
7. MCP client under the broker with tool annotations and pinned tool hashes (GH-64, GH-65). ADAPT the manager lifecycle in `companion-mcp/src/lib.rs` (MIT); governance is our addition.
8. Signed catalog, signed packages, install-versus-authorise-versus-execute, skill approval pinned to a content hash (GH-58 to GH-62, GH-56, GH-67). Format ideas only; own implementation.
9. Encrypted backup and restore (GH-81, GH-88). ADAPT envelope and AAD from `companion-checkpoint/src/sync.rs` 113-210 and write order 287-372 (MIT); key design is ours.
10. Memory import from other agents, read-only and untrusted until labeled (GH-48), plus conflict listing and near-duplicate proposals. ADAPT the adapter contract and conflict logic from Anamnesis (Apache-2.0). Do not ship the serve-back MCP door (GH-49).
11. Channel bridges with actor model and approval triggers, Edit and Send re-hash (GH-78, GH-79). Behaviour only.
12. Context meter, usage ledger, model picker with eligibility, plan mode (GH-13, GH-15, GH-16, GH-18).

15. Activity Recorder (opt-in), computer use through Cua with our gate, browser relay (GH-53, GH-68 to GH-70). Last because they carry the most privacy risk. Native-messaging pairing (GH-71) and the permissions page (GH-77) can ride along earlier as small wins.

## 5. Unknowns and limits

- The Workbench desktop app is closed. Its renderer and main bundle were not read; Team, Coding, Plugins, Computer Use and the approval UI were never exercised. The hands-on run stopped at the top-up wall (no funds), so task quality, speed, recovery and long-run behaviour are NOT VERIFIED. Only five screenshots exist locally.
- The docs (`Ghast_Doc`) describe an older macOS-Electron build and disagree with the observed 0.1.35 build on sign-in (GH-04). Wherever a claim rests on the docs it is labeled [D]. About 120 doc pages were not read.
- The shipped extension 0.1.9 is a different product from the Browser Relay extension the docs describe (different permission set). Neither was read beyond its manifest and file names.
- Pricing: only "download free, model usage billed" was found; no numbers, tiers or limits. Mobile: no mobile app is mentioned anywhere I read, which is not proof that none exists.
- Plugin and registry data was parsed, but only 2 of 496 package digests were recomputed, and no skill text was read. The per-plugin MIT files versus the missing repository licence is an open legal question.
- Anamnesis adapters, importer, exporter and 14 MCP tool bodies were not read; gmOS reconstruction (6,117 lines), extraction and consolidation were not read. Claims about them are limited to names and headers.
- Nothing was executed. No bypass of the Ghast command filter was run; no test suite of any Ghast repo was run. Everything labeled [V] means "read at the cited lines".
- `companion-app` (3,526 lines), `zero_g.rs` and the tray were not opened, so the native-bridge implementation and the 0G upload path are unreviewed.
- Surfaces of Kakurega itself were not re-tested here; "Kakurega state" comes from the decision docs, the registry and the README, so a few PARTIAL labels (GH-12, GH-17, GH-47, GH-75, GH-88) rest on those documents and not on running the product.
